Keep the human decision in the loop.

The interface should make deterministic checks, semantic review, source material, and officer judgment distinguishable—not collapse them into one opaque score.

05 / Visual system

Calm by default. Clear under scrutiny.

Use neutral surfaces and a strong type hierarchy so the decision and its evidence stand out. Reserve color for meaning, not decoration.

Color with a job

STATUS ALWAYS HAS A LABEL
Navy#20384F · structure
Teal#0E8C88 · brand/action
Pass#21824B · compliant
Review#946200 · conditional
Fail#B64747 · failed rule
PASS CONDITIONAL FAIL

Never rely on color alone to communicate status.

Type & spacing

READABLE AT REVIEW SPEED
HEADLINE / 40–56 pxClarity over spectacle.
Sans-serifReadable system stack for headings and body copy.
MonospaceClause IDs, reference numbers, raw extracted values.
8 px rhythmConsistent spacing, compact tables, generous section breaks.
✓
Built for keyboard, touch, and reduced motion

Use visible focus rings, meaningful headings, semantic tables, large tap targets, descriptive links, and `prefers-reduced-motion`. Responsive layouts should collapse the queue into a drawer or tab—not hide the evidence relationship.

06 / Existing-project fit

Fit the design to the code that exists.

We inspected the provided ZIP’s README, `app.py`, and `web/index.html`. The README calls this a full-stack platform, but the inspected server is Python’s standard-library `http.server` handler—not Flask.

Keep the current stack.This companion site is a separate design proposal. It does not alter the existing app or claim to integrate with any external procurement platform.
